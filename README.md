# local-ai-anonymizer (`laia`)

Pseudonymize a document with a model running on your own computer, send only the
sanitized text to a cloud AI, and put the real names back into the answer locally.

```
input file -> regex + local LLM detection -> tokens ([PERSON_1], [EMAIL_1], ...)
           -> mapping table (stays local) -> guard (fail closed) -> cloud AI
           -> response -> re-identify locally -> output
```

Status: research prototype, tested only on synthetic data. **It reduces risk; it does
not make a legal or policy determination.** Read [Limits](#limits) before using it on
anything real, and ask your institution's IT security office first.

## Install

Requires Python 3.10+ and [Ollama](https://ollama.com) with a local model
(tested with `gpt-oss:20b` and `gpt-oss:120b`).

```bash
pip install -e '.[test]'
ollama pull gpt-oss:20b
```

## Use

```bash
# 1. Anonymize locally. Writes out/sanitized-<id>.txt and a mapping file
#    under ~/.local/share/local-ai-anonymizer/maps/, encrypted with a passphrase
#    you choose (owner-only permissions; --no-encrypt to skip).
laia anonymize advising_note.txt --detector llm --model gpt-oss:20b

# 2. Build the prompt. The default backend is dry-run: nothing leaves the machine.
laia send out/sanitized-<id>.txt --task "Draft a follow-up email to the student." --backend file

# 3. Paste out/outgoing-<id>.txt into the AI tool, save its reply as out/response-<id>.txt, then:
laia reidentify out/response-<id>.txt --map ~/.local/share/local-ai-anonymizer/maps/map-<id>.json
```

`laia run` does all three. Backends: `dry-run` (default, writes the prompt only),
`file` (you or a chat session answer the prompt), `claude-cli` (sends via `claude -p`).

## What it does

- **Two detection layers.** Regex for structured identifiers (emails, phones, SSN-like
  numbers, 7-digit IDs, award numbers, cost centres, addresses, URLs, dates); a local LLM
  through Ollama for names, organisations, places and free-text identifiers. The model's
  strings are kept only if they occur verbatim in the input.
- **Consistent tokens.** Every mention of one person becomes the same `[PERSON_n]`,
  including surname-only mentions and one-letter misspellings, so the cloud model can
  still reason about who did what.
- **Fail closed.** The guard stops the document if a structured identifier pattern
  remains, if any original string from the mapping is still in the text, if a second
  LLM pass over the sanitized text finds a name, or if the local model fails. Documents
  marked CUI, ITAR, EAR99, export controlled or proprietary are refused outright.
- **No values on screen.** The tool prints counts and line numbers, never the original
  values: when you run it from inside an AI coding agent, its terminal output goes to
  the cloud too. File names are neutral hashes for the same reason (an input called
  `advising_Reyes.txt` does not name its outputs).
- **Quasi-identifier report.** GPA, money, course numbers, years, "only student",
  disability or visa mentions are reported, not removed; `--generalize-money` and
  `--generalize-gpa` coarsen them.

## Limits

- **Nicknames are separate people.** "Jon" is replaced, but as a different token from
  "Jonathan Reyes"; the cloud model may treat them as two people.
- **Common-word names.** Name parts that are ordinary words (Grant, Hope, Will) are not
  expanded on their own; the guard warns when one is left capitalised mid-sentence.
- **Quasi-identifiers are the hard part.** A rare major, a small class, an award amount
  and a date can identify a student with no name present. FERPA's test is whether a
  reasonable person in the school community could identify the student; this tool
  cannot decide that for you.
- **De-identified is a legal status, not a tool output.** Whether pseudonymized text from
  a restricted record may go to a given cloud tool is your institution's decision.
  The case studied here is the University of Houston under Texas law; other states and
  institutions differ on student and grant records.
- **Export-controlled and CUI material must not be processed this way at all.** The
  marker check is a backstop, not a classification.
- **The mapping table is as sensitive as the original record.** It is encrypted by default;
  keep it local and never commit it.

## Data

All test data are generated by `synth/generate.py`: invented names, fictional 555-01xx
phone numbers, never-issued 9xx SSN-like numbers, example.edu addresses and award
numbers with a "99" year. No real student or grant record was used.
